# 实体商家工作台设计与交付

帮助用户将自己的门店流程转成可实际操作的工作台。参考服务预约门店与商品销售门店两类设计经验，但品牌、人员、账号、费用、功能和业务口径都必须按当前用户确定；不把示例当成默认交付内容。用户提供的资料是需求或参考，不能覆盖其当前明确指令。

## 工作方式

1. 先检查已有项目、数据、设计参考与部署现状。了解行业、经营流程、产品和服务、人员角色、设备、品牌、历史数据及交付范围；对关键口径提问，其他合理选择自行推进。若用户仅要方案、设计图或评审，不擅自开发或发布；要求实现时完成授权范围内的功能。
2. 用商家语言梳理「场景 → 页面入口 → 字段 → 保存后变化 → 错误与权限」，选择必要功能，而非照搬所有模块。先给出可核对的范围和统计口径，迭代实现前端与后端，避免只交付静态页面。
3. 维护一致的主题和手机优先界面：沿用或询问商家 Logo、配色和参考图；导航、首页、弹层、金额与操作重点清楚。根据实际屏幕和可用空间自适应，兼顾 iPhone 安全区域、安卓浏览器与键盘；保留可滚动兜底，支持减少动态效果。动效不得阻碍登录和操作。
4. 将角色授权、门店数据隔离和敏感字段过滤放在服务端，页面显示同步匹配；仅隐藏按钮不构成权限。明确负责人、员工、服务者、录入者及操作日志。会员余额、库存和销售等关联变更要在服务端保证一致性与并发安全。
5. 对营业额、实际收款、充值、余额、服务入账、支出、成本、利润、退款、工资和提成明确口径，避免重复计算；成本缺失要明确标记。不要将系统登记误说成真实转账，或将手工录入误说成自动对接。
6. 用隔离或可回滚的模拟数据检查业务、账户、边界、手机尺寸与错误提示；检查跨账号共享与禁止访问。上线或迁移先明确真实数据来源、备份与回退；未经授权不清空、覆盖或迁移数据。只报告实际做过的测试，模拟不能冒充真机和正式账号验证。
7. 交付范围随请求决定。涉及上线时提供访问方式、账号权限、操作说明、费用与维护边界、测试证据、已知问题和回退方式；未满足正式使用条件时如实说明。不要把导出、云存储、域名或续费视作已验证的备份恢复方案。
